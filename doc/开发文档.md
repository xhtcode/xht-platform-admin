## 一、项目概述

### 1.1 项目用途与形态

XHT Platform Admin 是纯前端 SPA 管理后台，前端产物通过 Nginx 反向代理对接后端网关。业务域包含系统管理（用户/角色/部门/菜单/字典/公告/文件/消息/OAuth2 客户端/地区）、代码生成器（数据源/表/字段/模板/类型映射）、监控中心（在线用户/操作日志）、工作台与登录/授权页。

### 2.2 路由的两层结构（新增页面必须两边对齐）

- **静态路由**：`src/router/modules/static.ts`，仅 `/login`、`/oauth2`、`/redirect/:path(.*)`、`/:path(.*)*`。
- **动态路由**：登录后 `permission.ts` 守卫调用 `routes.store.ts` 的 `generateRoutesAtBack()` → `getRouters()`（`/sys/user/profile/routers`）→ `formatBackRoutes()` 用 `import.meta.glob('../../views/**/*.{vue,tsx}')` 把后端返回的 `component` 字符串（形如 `/system/user/index`）映射为真实组件。
- 因此：**页面文件路径必须与后端菜单里配置的 `component` 字符串逐字符对应**，否则菜单可点但页面空白。`meta.menuType === 'M'` 的节点被强制映射为 `@/layout/index.vue`。

### 2.3 `src/service` 四分层

`service/api/<域>/<模块>.api.ts`（只放请求函数，薄封装）｜`service/model/<域>/<模块>.model.ts`（请求/响应 DTO 与字面量联合类型）｜`service/enums/<域>/<模块>.enum.ts`（`DictEnum` 常量对象）｜`service/constant/index.ts`（路径、请求头、默认值等全局常量）。

### 2.4 新增代码放哪里（决策表）

| 我要加的东西 | 落位 |
| --- | --- |
| 一个新的业务列表页 | `src/views/<域>/<模块>/index.vue` + `index` 同级的 `<模块>.data.ts` + `components/<模块>-form.vue` |
| 一个只在本模块复用的弹窗/表单 | `src/views/<域>/<模块>/components/xxx-form.vue` |
| 一个跨模块复用的组件 | `src/components/<分类>/xht-xxx/index.vue` + `types.ts` |
| 一个新的后端接口 | `src/service/api/<域>/<模块>.api.ts` 追加导出函数 |
| 新接口的 DTO | `src/service/model/<域>/<模块>.model.ts` |
| 新的枚举/字典常量 | `src/service/enums/<域>/<模块>.enum.ts` |
| 新的全局状态 | `src/store/modules/<模块>.store.ts`，并在 `pinia-persist.ts` 决定是否持久化 |
| 新的组合式逻辑 | `src/hooks/use-<能力>.ts` |
| 新的全局类型 | `src/typings/*.d.ts`（按领域拆文件，不要都塞进 `global.d.ts`） |

## 四、代码写法规范

### 4.1 `<script setup>` 与宏顺序（eslint 强制）

eslint `vue/define-macros-order` 要求：`defineOptions → defineProps → defineEmits → defineSlots`；`vue/block-order` 要求块顺序 `script → template → style`；`vue/padding-line-between-blocks` 要求块之间空行。

✅ 推荐（`src/components/dict/xht-dict-select/index.vue` 结构）
```vue
<script setup lang="ts">
import type { XhtDictSelectEmits, XhtDictSelectProps } from '@/components/dict/xht-dict-select/types'

defineOptions({ name: 'XhtDictSelect', inheritAttrs: true })
const props = withDefaults(defineProps<XhtDictSelectProps>(), { clearable: true })
const emits = defineEmits<XhtDictSelectEmits>()
</script>

<template>...</template>

<style scoped lang="scss">...</style>
```
- `defineOptions` 统一放 script 顶部、import 之后。
- 全部页面/组件均为 `lang="ts" setup`，**不写 `export default defineComponent`**。

### 4.2 自动导入

`unplugin-auto-import` 已注入 `vue` + `@vueuse/core` + `ElementPlusResolver`，`ref/reactive/computed/toRefs/onMounted/watch/nextTick/defineAsyncComponent/useTemplateRef/ElMessage/ElMessageBox` 等**无需 import**。

✅ 推荐
```ts
// src/views/system/user/index.vue（ref / reactive / toRefs / onMounted 均未 import）
const state = reactive<TableQueryPageState<SysUserQueryRequest, SysUserResponse>>({ ... })
onMounted(async () => { await handlePageQuery() })
```

❌ 避免：`import { ref } from 'vue'`（历史残留写法，现已清零，且被 eslint 拦截）

✅ 已闭环（2026-10-22）：原 6 处显式导入已全部删除，并在 `eslint.config.ts` 增加 `@typescript-eslint/no-restricted-imports`（`paths: [{ name: 'vue', allowTypeImports: true, importNames: [...] }]`）——除 `import type { ... } from 'vue'` 与入口 `main.ts` 的 `createApp` 外，`ref/reactive/computed/onMounted/nextTick/toRef/shallowRef/useTemplateRef` 等再写显式导入会直接报错。新增页面照此写法即可。

另一注意点：`vite.config.ts` 里 `AutoImport({ dts: false })`、`Components({ dts: false })`，但 `src/typings/auto-imports.d.ts`、`components.d.ts` 仍存在于仓库且内容陈旧（如 `components.d.ts` 仍声明已删除的 `DeptPostSelect`）。**不要依赖这两个文件判断组件是否存在**，以 `src/components/**/index.vue` 实际文件为准。【待团队统一：两份 d.ts 是否删除/重新生成】

### 4.3 类型定义

- DTO 只允许定义在 `src/service/model/`。**禁止在 `.vue` 里内联 `interface XxxResponse`**。
- 跨文件只用类型时一律 `import type`（eslint `@typescript-eslint/no-import-type-side-effects: error`）。
- 全局通用类型（`PageQueryRequest`、`PageResponse`、`MetaResponse`、`BasicResponse`、`ModeIdType`、`DictEnum`）已在 `src/typings/*.d.ts` 声明，直接使用，不重复定义。
- `any` 未被禁止（eslint 显式 `no-explicit-any: off`），但业务 DTO 不应出现；`routes.store.ts` 对后端路由用了 `any`，属已知妥协。

### 4.4 状态管理

- 一律 Pinia **setup store**，返回具名对象；`storeToRefs` 解构响应式。
- 持久化统一走 `pInIaPersistConfig(key)`（`src/store/pinia-persist.ts`），key 自动加 `xht_` 前缀。

## 五、接口请求规范

### 5.1 请求内核契约（`src/utils/request.ts`）——不要改

- axios 实例：`baseURL = VITE_BASE_API`、`timeout: 50000`、`withCredentials: true`、`qs.stringify(params, { arrayFormat: 'repeat' })`。
- 请求拦截器自动注入：`Authorization: Bearer <token>`（`config.skipToken` 可跳过）、`X-Trace-Id`（UUID）、`X-User-Id`、`X-User-Account`；GET 追加 `_t` 时间戳。
- 响应信封（`src/typings/global.axios.d.ts` 扩展 axios 模块）：
  ```ts
  export interface ApiResponse<T = unknown> {
    code: number; msg: string; data: T          // code 仅 200 视为成功，msg 原样透传
    dataType?: 0 | 1; encryptData?: string      // 1 表示加密（当前提示"加密暂未实现"）
    success?: boolean                           // @deprecated
  }
  ```
- 两个导出职责不同：`request<T>(config): Promise<ApiResponse<T>>` 用于普通业务请求，**返回业务信封本身**，调用方自行取 `.data`；`requestBlob<T>(config): Promise<AxiosResponse<T>>` 用于文件流（`responseType: 'blob' / 'arraybuffer'`），配套 `handleDownloadFile`。

### 5.2 api 文件写法（固定四段式）

✅ 推荐（`src/service/api/system/user.api.ts` 抽象）
```ts
import request from '@/utils/request'
import type { ApiResponse } from 'axios'
import type { SysUserOperationRequest } from '@/service/model/system/user.model'

// 鉴权域换 VITE_AUTH_API_PREFIX，生成器域换 VITE_GENERATE_API_PREFIX
const baseURL: string = import.meta.env.VITE_ADMIN_API_PREFIX
enum Api { CREATE = '/sys/user/create', UPDATE = '/sys/user/update/' }

export const saveSysUser = (data: SysUserOperationRequest): Promise<ApiResponse<void>> => {
  return request<void>({ url: Api.CREATE, baseURL, method: 'post', data: data })
}
```
约定：
1. 文件顶部 `const baseURL = import.meta.env.VITE_*_API_PREFIX`；21 个 api 文件全部遵循。
2. 路径集中到文件内 `enum Api`，**不在函数体内写裸字符串**。
3. 路径参数用模板串拼接且**保留结尾斜杠**：`Api.UPDATE + `${data.id}``（对应后端 `/sys/user/update/`）。
4. 每个函数显式标注返回类型 `Promise<ApiResponse<T>>`；无返回体写 `ApiResponse<void>`。
5. 涉及请求体的接口用 `post`（`b7a7e53` 提交专门把多个 get 改成 post 以支持 body 传参）。
6. 只有请求、无业务逻辑：不在 api 层做提示、弹窗、状态变更。

### 5.3 入参/出参

- 查询请求 `extends PageQueryRequest`（含 `size/current/ascName/descName/quick/keyWord`），分页响应 `PageResponse<T>`（`records/total/pages/current/size`）；主键参数一律 `ModeIdType`。
- 后端字段名直接映射，**不做前端驼峰转换**（`userName`、`deptId` 原样）。

### 5.4 错误处理（本仓库最容易被写错的地方）

- 成功判定只有一个条件：`code === 200`。
- 失败时拦截器统一 `useMessage().error(msg)` 弹提示，并 `throw new BusinessError(code, msg, data)`。
- 文案"完全透传后端 `msg`，前端不改写、不映射、不兜底"。
- `code === 424` 或 HTTP 401（且非 `skipToken`、且已登录）→ `handleSessionExpired()`：弹确认框让用户选择"前往登录 / 暂不跳转"，**不自动跳转**。

✅ 推荐（来自 `use-crud-hooks.ts`：只记日志、不重复提示、不向上抛；按业务码分支时才 catch 处理）
```ts
try {
  const response: ApiResponse<PageResponse<Res>> = await queryPageApi(queryParams.value)
  state.tableList = response.data.records
} catch (error) {
  console.error('数据查询失败:', error)          // 提示已由拦截器给出
  if (isBusinessError(error) && error.code === 50104) { /* 按业务码引导用户 */ }
} finally {
  state.loadingStatus = false
}
```

❌ 避免（拦截器已提示过，再弹一次会重复）
```ts
try { await saveSysUser(data) } catch (e) { useMessage().error('保存失败') }
```

### 5.5 公开接口

登录、验证码等免登录接口必须带 `skipToken: true`，否则会触发登录态失效流程：
`request<...>({ url: Api.CAPTCHA, baseURL, method: 'get', skipToken: true })`。

## 六、组件开发规范

### 6.1 拆分原则

- 页面只做编排（查询区、工具栏、表格、弹窗挂载点），表单项超过约 6 个或包含独立业务逻辑时拆 `components/xxx-form.vue`。参考 `views/system/user/`（`index.vue` + `components/user-form.vue` + `components/user-role-form.vue` + `user.data.ts`）。
- 只在本模块复用的组件留在 `views/<域>/<模块>/components/`；跨模块复用才上提到 `src/components/<分类>/`。
- 单文件行数**不设硬性上限**（已定，不做行数考核）；但页面仍应职责单一，表单项超过约 6 个或包含独立业务逻辑时，按本节第一条拆 `components/xxx-form.vue`。

### 6.3 Emits

**已定（2026-10-22 统一）**：按分层两种写法，各自内部保持一致。

| 写法 | 文件数 | 适用范围 |
| --- | --- | --- |
| `defineEmits(['success'])` 数组 | 19 | 仅 `views/**` 业务弹窗/表单，且清一色是 `['success']` |
| `defineEmits<XxxEmits>()` 泛型 | 23 | `src/components/**` 通用组件、`layout/**` 部件 |

- 通用组件必须用泛型，emits 类型写同目录 `types.ts`，命名 `XxxEmits`；业务弹窗可继续用数组。
- 同一组件内不要混用两种写法；`v-model` 相关事件优先 `defineModel`（见 6.4），不再手写 `update:xxx`。
- 2026-10-22 已把 `src/components/**` 下最后 5 处数组写法改为泛型（`code-monaco-editor`、`xht-pagination`、`menu-tree-select` 补 `Emits` 接口；`dept-tree-select`、`menu-tree-check` 新建 `types.ts`，内联 `Props` 一并迁出）；`layout/components/tags-view/index.vue` 中未被使用的 `emits('refresh')` 声明已删除。

- 事件名：`emit` 时用单个小写单词（`emits('success')`、`emits('pagination')`），多词用 kebab-case（`emits('remove-tag')`）；模板监听用 kebab-case（`@click-node`、`@pagination`、`@refresh`）。
- emits 类型定义在 `types.ts`，参照 `src/components/table-tool-bar/types.ts`：`export interface EmitsType { (e: 'refresh'): void; (e: 'column'): void }`。

## 八、新增功能开发流程

以"新增一个用户管理列表页"为例（现有 `views/system/user` 即此流程的产物）：

4. **写列表页**：`src/views/system/xxx/index.vue`，`defineOptions({ name: 'SysXxxViewIndex' })`，按 6.7 套路搭 `state + useTableQueryPageHooks + 查询区 + table-tool-bar + el-table + xht-pagination`。

## 九、禁止事项 & 踩坑提醒

1. **禁止绕过动态路由映射**。页面必须与后端菜单 `component` 字符串对齐（`routes.store.ts` 用 `import.meta.glob('../../views/**/*.{vue,tsx}')` 映射为 `../..${component}`），对不上就是"菜单能点、页面空白"。`meta.menuType === 'M'` 才是目录节点（自动指向布局）。
2. **禁止调用 `router.clearRoutes()`**。`src/router/index.ts` 用 `dynamicRouteRemovers` 数组精确移除动态路由；`clearRoutes()` 会把登录页、404 等静态路由一起清掉。登出/切换账号走 `resetRoutes()` → `removeDynamicRoutes()`。
3. **禁止随意修改 `src/utils/request.ts` 的拦截器契约**。`request<T>` 返回业务信封、错误统一提示、`code === 200` 才成功、`BusinessError` 抛出规则——全站 21 个 api 文件、上百个接口依赖它。要改先全量回归。
4. **禁止在调用方重复弹错误提示，或吞掉异常后自己再提示**。文案由拦截器透传后端 `msg`；`catch` 里只做 `console.error` 与状态复位。
5. **禁止在页面里直接用 `localStorage.clear()` / `sessionStorage.clear()` 之外的粗暴清理**。登出清理统一 `clearSessionPersist()`（保留 `xht_theme`），否则用户主题、布局偏好每次登录被重置。
6. **禁止硬编码颜色/圆角/边框色**。必须 `var(--xht-xxx)` / `var(--el-xxx)`，否则暗黑模式失效。
7. **禁止在 `src/service/model` 之外重复定义接口 DTO**。不要在 `.vue` 里内联写 `interface XxxResponse`；不要在页面里再定义一遍后端字段。
8. **不要往 `src/utils/module/` 继续加文件**。目录名原为历史拼写错误 `moudle`，已于 2026-10-22 统一重命名为 `module` 并全量替换引用（现有 `RegularUtils.ts`、`element.ts`）；**禁止再把拼写改回 `moudle`，也禁止新建其它拼写变体目录**。新工具函数放 `src/utils/` 顶层或对应 `hooks/`。
9. **禁止新增第三方依赖**。当前 Vite 8 / TS 6 / Vue Router 5 / Element Plus 2.14 / Pinia 4 互相咬合，新增依赖需先评估兼容性并统一走 pnpm。【待团队统一：依赖引入的审批流程】
10. **禁止改动 `package.json` 的 `build` 脚本结构**（`run-p type-check "build-only {@}"`）。类型检查是构建闸门，去掉它会把类型错误带上生产。
11. **不要把后端域名写死在前端**。产物内只有相对路径 `/api`，生产由 Nginx 反代并去掉 `/api` 前缀（README「生产部署要求」有 nginx 片段），同时需 `try_files $uri $uri/ /index.html;` 支持 history 路由。
12. **不要凭目录名猜业务**。`src/views/monitor/blog/` 实际是**操作日志**（`blog.api.ts` → `queryBLogPage`），与"博客"无关；`blog` 的 `B` 大写是后端命名（`queryBLogPage`）。
13. **不要在 `src/components/**` 下把组件写成 `xxx.vue` 还指望自动注册**。自动注册只匹配 `src/components/**/index.vue`。
14. **不要轻信 `src/typings/components.d.ts` / `auto-imports.d.ts`**。`vite.config.ts` 已设置 `dts: false`，这两份文件是历史产物，内容可能包含已删除组件（如 `DeptPostSelect`）。以实际文件与构建结果为准。
15. **改 `src/store` 时注意循环依赖**。store 之间、store 与 `request.ts` 之间互相引用必须用动态 `import()`，静态 import 会形成 `request → store → api → request` 环。
16. **`v-authorization` 的权限编码必须与后端菜单按钮编码完全一致**，否则按钮永久隐藏；超管（`userType === 1`）在 `isAuthorized` 中直接放行，本地测权限时注意区分账号。

> 单文件行数不设硬性上限（已定），因此这里不作为禁止事项；判断标准是职责是否单一，而非行数。
