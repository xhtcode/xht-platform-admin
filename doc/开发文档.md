# XHT Platform Admin 前端开发规范

> 所有条目由仓库现有代码实证归纳。约定优先级：**现有代码 > 本文档 > 个人偏好**；冲突时先按现有主流写法实现，再讨论改文档。缺少证据或多写法并存的条目标注【待团队统一】，汇总见附录。

## 一、项目概述

纯前端 SPA 管理后台，Nginx 反代对接后端网关。业务域：系统管理（用户/角色/角色分类/部门/菜单/字典/公告/文件/消息/OAuth2 客户端/地区/行政区划）、代码生成器（数据源/表/字段/模板/类型映射）、监控中心、工作台与登录/授权页。

**技术栈**：Vue 3.5（全量 `<script setup>`）+ TS 6（strict）+ Vite 8（Rolldown）+ Vue Router 5（静态 + 后端动态路由）+ Pinia 4（setup store + 持久化）+ Element Plus 2.14 + UnoCSS 66 + Sass（变量全局注入）+ axios（统一封装 `src/utils/request.ts`）。质量工具：oxlint + eslint + prettier + vue-tsc。包管理 pnpm（`nodeLinker: hoisted` 配在 `pnpm-workspace.yaml`，pnpm 12 不读 `.npmrc` 的 node-linker），Node `^22.18 || >=24.12`。

**命令**：

| 命令 | 说明 |
| --- | --- |
| `pnpm dev` | 3000 端口，代理 `/api` 并去掉前缀 |
| `pnpm build` | type-check 与构建**串行**，类型检查是构建闸门，勿改脚本结构 |
| `pnpm build:prod/test/dev` | 不带类型检查 |
| `pnpm type-check` / `pnpm lint` / `pnpm format` | lint 为 oxlint → eslint 串行且都会改文件；format 只覆盖 `src/` |

**已定：不引入测试框架**。质量闸门 = `pnpm type-check` + `pnpm lint` + 人工自测。

**入口链路**：`main.ts` 依次 `setupRouter → setupStore → setupPermission → setupElIcons → setupDirectives → mount`。

**网关前缀**（`.env.*`）：axios `baseURL = VITE_BASE_API`（`/api`）；业务前缀 `VITE_ADMIN_API_PREFIX`（`/api/admin`，绝大多数接口）、`VITE_AUTH_API_PREFIX`（`/api/auth`）、`VITE_GENERATE_API_PREFIX`（`/api/generate`）。生产由 Nginx 反代 `/api` 并去前缀，域名不写死在前端。

## 二、目录与落位

| 要加的东西 | 落位 |
| --- | --- |
| 业务列表页 | `src/views/<域>/<模块>/index.vue` + 同级 `<模块>.data.ts` |
| 本模块弹窗/表单 | `src/views/<域>/<模块>/components/xxx-form.vue` |
| 跨模块组件 | `src/components/<分类>/xht-xxx/index.vue` + 同目录 `types.ts`（`index.vue` 自动全局注册） |
| 接口 / DTO / 枚举 | `src/service/{api,model,enums}/<域>/<模块>.{api,model,enum}.ts` |
| 全局状态 | `src/store/modules/<模块>.store.ts`（`pinia-persist.ts` 决定持久化） |
| 组合式逻辑 | `src/hooks/use-<能力>.ts` |
| 全局类型 | `src/typings/*.d.ts`（按领域拆文件） |

域目录固定 `dashboard / generate / login / monitor / oauth2 / other / system`，新增域先确认。

**路由两层结构**：静态路由只有 `/login`、`/oauth2`、`/redirect`、404（`router/modules/static.ts`）；业务路由登录后由后端下发，`routes.store.ts` 用 `import.meta.glob('../../views/**/*.{vue,tsx}')` 把菜单 `component` 字符串（如 `/system/user/index`）映射为组件——**页面路径必须与菜单 `component` 逐字符一致，否则菜单能点、页面空白**。`meta.menuType === 'M'` 强制映射为布局。静态免登录页在 `static.ts` 加记录并写 `meta.ignoreAuth: true`（不存在 whiteList）。

**service 四分层**：api（只放请求函数）｜model（DTO 与字面量联合类型，全仓唯一放 DTO 处）｜enums（`DictEnum` 常量）｜constant（全局常量）。

## 三、命名规范

**文件**：页面目录 kebab-case；service 文件 `<模块>.{api,model,enum}.ts`；多词模块用 `.` 分隔（`dict.item.api.ts`）；store `<模块>.store.ts`；hooks `use-<能力>.ts`；组件 `xht-xxx/index.vue`。

**组件 `defineOptions({ name })`**（eslint 强制）：页面 `Sys<模块>ViewIndex`；通用组件大驼峰对齐目录名；业务弹窗 `<业务>Form`；布局件 `Layout*/Menu*/Tags*`。

**变量与函数**：布尔 `xxxStatus / hasXxx / isXxx`；事件 `handle` 前缀；分页/表格状态对象统一叫 `state`；常量大写下划线。

**api 函数**：`save / update / remove<Domain>ById(s) / query<Domain>Page|List|Tree|ById`，非实体查询用 `get<X>`。

**模型类型后缀**：

| 后缀 | 用途 |
| --- | --- |
| `<Domain>QueryRequest` | 查询入参，`extends PageQueryRequest` |
| `<Domain>OperationRequest` | 增改入参，`extends ...Vo, BasicFormRequest` |
| `<Domain>Response` | 出参，`extends MetaResponse` |
| `<Domain>Vo` | 组合视图对象 |
| `<Domain>Props` / `<Domain>Emits` | 组件契约，放组件目录 `types.ts` |

- 域前缀：系统 `Sys`、生成器 `Gen`，其余不加。主键一律 `ModeIdType`，禁写 `string | number`。
- `type` vs `interface`：**值用 type，形状用 interface**。DTO 全是 `interface`（不要改写成 type）；字面量值域（`export type UserKind = 1 | 2 | 3`）用 `type`；必须联合形态的字典结构用 `type`（`DictEnum<T, K>`）。
- 泛型：单参 `T`；多参按语义（`TableQueryPageState<Req, Res>`）；错误类型写 `TError` 不用 `E`。
- 值域类型**不加 `Type`/`Types` 后缀**：删后缀丢语义的用 `Kind`（`UserType` → `UserKind`）；与 lib.dom 全局撞名时加语义词不要硬删（`StorageType<T>` → `LocalStorageSchema`）；唯一例外 `ModeIdType`。
- 禁止：绕过 `ModeIdType`、与浏览器全局同名的类型命名、任何第二套响应信封。

**枚举**：`export const xxxEnum: DictEnum<T, 'A'|'B'>`，项 `{ label, value, type? }`，键全大写；`type` 用 Element Plus 语义色供 `<xht-enum-tag>`，不写硬编码色值；文件名单数 `*.enum.ts`。

**store**：id 用 `snake_case`，导出 `use<模块>Store`，setup 风格 + `pInIaPersistConfig(key)` 持久化；hooks 一律返回对象不返回数组。

## 四、代码写法

- **宏与块顺序**（eslint 强制）：`defineOptions → defineProps → defineEmits`；块顺序 `script → template → style`，块间空行。
- **自动导入**：`vue` / `@vueuse/core` / `ElMessage` 等**无需 import**，显式 `import { ref } from 'vue'` 会被 eslint 拦截（仅 `import type` 与 `main.ts` 例外）。`src/typings/{auto-imports,components}.d.ts` 是插件生成物，**手改会被覆盖**，无需检查。
- **类型**：DTO 只放 `src/service/model/`，**禁止在 `.vue` 内联 `interface XxxResponse`**；跨文件只用类型一律 `import type`（全仓已统一）；全局类型（`PageQueryRequest`、`PageResponse`、`MetaResponse`、`ModeIdType`、`DictEnum`）直接用不重复定义；新增代码不用 `any`。
- **状态管理**：Pinia setup store + `storeToRefs`；**store 之间、store 与 request 之间互相引用必须动态 `import()`**，静态 import 会形成 `request → store → api → request` 循环；清理登录态用 `clearSessionPersist()`，禁 `localStorage.clear()`（会重置用户主题偏好）。
- **不要重复造轮子**：请求 `request<T>/requestBlob<T>`；提示 `useMessage()/useMessageBox()`；分页列表 `useTableQueryPageHooks/useTableQueryListHooks`；字典 `useDictHooks` + `<xht-dict-select>`；权限 `v-authorization` / `isAuthorized()`；下载 `handleDownloadFile`；深拷贝 lodash；防抖节流 @vueuse/core。
- **注释**：中文 JSDoc；关键「为什么」写进注释。`console.error/warn` 保留（生产未删，线上排障依据），调试 log 提交前删；**不要为生产静音删请求链 catch**，静音走构建层（如 `drop_console`）。
- **格式**：无分号、单引号、2 空格、行宽 150、LF；template 单行最多 3 属性、多行每行 1 个、强制自闭合。

## 五、接口请求

### 5.1 请求内核契约（`src/utils/request.ts`）——不要改

- 拦截器自动注入 `Authorization`（`skipToken: true` 可跳过，免登录接口必须带）、`X-Trace-Id`、`X-User-Id` 等。
- `request<T>` 返回**业务信封本身**，调用方取 `.data`；`requestBlob<T>` 用于文件流，配 `handleDownloadFile`。

```ts
export interface ApiResponse<T = unknown> {
  code: number; msg: string; data: T   // 仅 code === 200 视为成功；msg 原样透传
}
```

### 5.2 api 文件四段式

```ts
const baseURL: string = import.meta.env.VITE_ADMIN_API_PREFIX   // 1. 前缀
enum Api { CREATE = '/sys/user/create', UPDATE = '/sys/user/update/' }  // 2. 路径收进 enum

// 3. 函数 save/update/remove/query 系列，显式返回 Promise<ApiResponse<T>>
export const saveSysUser = (data: SysUserOperationRequest): Promise<ApiResponse<void>> => {
  return request<void>({ url: Api.CREATE, baseURL, method: 'post', data: data })
}
```

- 路径参数模板串拼接且**保留结尾斜杠**；涉及请求体一律 `post`；api 层只发请求，不做提示与状态变更。
- 查询入参 `extends PageQueryRequest`，分页响应 `PageResponse<T>`；后端字段名直接映射，**不做驼峰转换**。

### 5.3 错误处理（最易写错）

- 成功判定唯一条件 `code === 200`；失败由拦截器统一弹后端 `msg` 并抛 `BusinessError`，**文案不改写不映射**。
- `code === 424` 或 HTTP 401 → `handleSessionExpired()` 弹确认框，不自动跳转。
- **catch 只做 `console.error` + 状态复位，禁止再弹提示**（会双弹）；需要按业务码分支时才在 catch 里处理。
- **请求链必须带 `.catch`**（2026-11-24 全仓统一）：`.then().finally()` 一律补 `.catch((error) => console.error('xxx失败:', error))`；`confirm` 用户取消（reject `'cancel'`）**不做特判**，走同一条 catch。

```ts
useMessageBox().confirm('此操作将永久删除用户, 是否继续?').then(async () => {
  await removeSysUserById(row.id); await handlePageQuery(); useMessage().success('删除用户成功!')
}).catch((error) => console.error('删除用户失败:', error))
```

## 六、组件规范

- **拆分**：页面只做编排；表单项多或有独立业务逻辑时拆 `components/xxx-form.vue`；跨模块复用才上提 `src/components/`。单文件行数**不设上限**（已定），只看职责是否单一。
- **Props**：泛型 + `withDefaults`，类型放同目录 `types.ts`；对象/数组默认值必须工厂函数。不用运行时对象声明式 props。
- **Emits**：业务弹窗用数组 `defineEmits(['success'])`（统一只发 `success`）；通用组件必须泛型 `defineEmits<XxxEmits>()` 且类型写 `types.ts`。事件名单词小写、多词 kebab-case，模板监听用 kebab-case。同一组件不混用两种写法。
- **v-model / ref**：新组件优先 `defineModel`，不手写 `update:xxx`；模板 ref 统一 `useTemplateRef`。
- **自动注册**：只有 `src/components/**/index.vue` 参与自动注册（免 import）；其他位置的组件必须显式或异步引入。

### 6.1 弹窗标准模式

```vue
<script lang="ts" setup>
defineOptions({ name: 'UserForm' })
const emits = defineEmits(['success'])
const state = reactive<AddUpdateOption<SysUserOperationRequest>>({
  title: '新增用户', visibleStatus: false, operationStatus: 'create', loadingStatus: false,
  addUpdateForm: { ...sysUserOperationForm },
})
const show = async (type: 'create' | 'update', id: ModeIdType) => { /* 打开拉详情；title 置「修改用户」 */ }
const close = () => { /* 守卫 if (state.loadingStatus) return；复位表单与 operationStatus */ }
defineExpose({ show })
</script>
```

**提交统一「三元选函数」写法**（已定 2026-11-24，替代 if/else 重复链；校验失败分支复位 loading 并提示，略）：

```ts
const request = state.operationStatus === 'create' ? saveSysUser : updateSysUser
request(addUpdateForm.value)
  .then(() => {
    emits('success')
    useMessage().success(`${state.title}成功`)
    state.loadingStatus = false   // ⚠️ 必须在 close() 之前：close 有 if (loadingStatus) return 守卫，不复位则提交成功后弹窗关不掉
    close()
  })
  .catch((error) => console.error('提交用户失败:', error))
  .finally(() => {
    state.loadingStatus = false
  })
```

title 统一「新增X / 修改X」，成功提示 `` `${state.title}成功` ``，catch 日志「提交X失败:」；两分支行为不同（如模板保存回写 `id`）时不强行合并。父页侧：`defineAsyncComponent` 引入 + `useTemplateRef` + `@success="handlePageQuery"`。

### 6.2 列表页标准套路

1. `state = reactive<TableQueryPageState<Req, Res>>({ queryParams, total, pages, searchStatus, tableList, selectedRows, loadingStatus, singleStatus, multipleStatus })`
2. `useTableQueryPageHooks<Req, Res>(state, queryXxxPage)` 得到 `handlePageQuery / handleSelectionChange`（树形列表用 `useTableQueryListHooks`）
3. 列显隐写 `*.data.ts` 的 `ColumnConfig<Res>`，页面内 `columnOption` 控制 `v-if`
4. 查询区 `el-form + el-row/el-col`（`:xl="4" :lg="8" :md="8" :sm="12" :xs="24"`），关键字/高级搜索由 `searchStatus` 切换
5. 工具栏 `<table-tool-bar>`，按钮挂 `v-authorization="['sys:xxx:create']"`
6. 表格 `v-loading` + `<xht-column-index>` + `<xht-pagination v-model:current-page v-model:page-size @pagination>`

### 6.3 提示与样式

- 提示一律 `useMessage()` / `useMessageBox()`，**禁止直接 `ElMessage`**（拦截器内部的 `ElMessageBox` 不算违规）。
- 样式统一 `<style lang="scss" scoped>`；布局间距优先 UnoCSS 原子类；**颜色/圆角/边框一律 CSS 变量** `var(--xht-*)` / `var(--el-*)`，硬编码色值暗黑模式失效；页面容器用 `xht-view-container`。
- SCSS 变量由 vite `additionalData` 全局注入，正常不需要手动 `@use`。
- 图标：本地 SVG 用 UnoCSS 类（`i-menu-*` / `i-common-*` / `i-login-*`）；Element Plus 图标页面内显式 `import` 后 `:icon` 传递。

以新增「xxx 管理」为例：

1. `service/model/system/xxx.model.ts`：`QueryRequest extends PageQueryRequest`、`OperationRequest`、`Response extends MetaResponse`、`Vo`，主键 `ModeIdType`。
2. `service/enums/system/xxx.enum.ts`（如需）+ `service/api/system/xxx.api.ts`（按 §5.2 四段式）。
3. `views/system/xxx/xxx.data.ts`：`xxxOperationForm` / `xxxOperationRules` / `xxxColumnOption`。
4. `views/system/xxx/index.vue`：按 §6.2 套路。
5. `views/system/xxx/components/xxx-form.vue`：按 §6.1 弹窗模式。
6. 后端配菜单：`component` 填 `/system/xxx/index`（与实际路径逐字符一致），按钮权限编码与 `v-authorization` 对齐。
7. `pnpm type-check` → `pnpm lint` → `pnpm dev` 自测主流程与权限 → 提交 `develop`。

## 九、禁止事项 & 踩坑

1. 页面路径必须与后端菜单 `component` 逐字符一致，否则白屏；`meta.menuType === 'M'` 才是目录节点。
2. 禁止 `router.clearRoutes()`（会清掉静态路由）；登出走 `resetRoutes()`。
3. 禁止改 `src/utils/request.ts` 拦截器契约（全站接口依赖），要改先全量回归。
4. 禁止调用方重复弹错误或吞异常自己提示；catch 只 `console.error` + 状态复位；请求链必带 catch（§5.3）。
5. 禁止 `localStorage.clear()` 粗暴清理；统一 `clearSessionPersist()`。
6. 禁止硬编码颜色/圆角/边框，一律 CSS 变量。
7. 禁止在 `service/model` 之外内联 DTO。
8. 不要往 `src/utils/moudle/` 加文件（目录名是历史拼写错误，暂不重命名）；新工具放 `src/utils/` 顶层或 `hooks/`。
9. 新增依赖先评估，pnpm 安装；图表/编辑器等重依赖先团队过一遍【待团队统一：审批流程】。
10. 禁止改 `build` 脚本结构（类型检查是构建闸门）。
11. 后端域名不写死在前端，生产靠 Nginx 反代（需 `try_files ... /index.html` 支持 history 路由）。
12. 不要凭目录名猜业务：`views/monitor/blog/` 实际是**操作日志**（`queryBLogPage`）。
13. 组件自动注册只匹配 `src/components/**/index.vue`。
14. 不要手改 `components.d.ts` / `auto-imports.d.ts`（插件生成物）。
15. store 实例只能在调用期获取（函数体内 `useXxxStore()`），禁止在模块求值期访问其他模块的运行时导出；store 与 request、api 层之间的静态循环依赖是既有事实（request → user.store → api → request），新增跨 store 引用直接静态导入即可，无需动态 `import()`（routes.store 的动态导入已因无效拆包告警于 2026-11-24 移除）。
16. `v-authorization` 编码必须与后端菜单按钮编码完全一致，否则按钮永久隐藏；超管直接放行，本地测权限注意账号。
